# Протокол встречи из видео

Рабочий процесс создания итогового отчета (протокола) из видеозаписи встречи.

## Шаги

1. **Прочитать конфигурацию.** Открыть файл `.env` в корне проекта и взять значения `VIDEO_FOLDER` (папка с видео) и `OUTPUT_FOLDER` (папка для итоговых протоколов). Если `VIDEO_FOLDER` пустая — спросить у пользователя путь и записать его в `.env`. Если `OUTPUT_FOLDER` пустая — протоколы сохраняются в `artifact/` внутри проекта. Путь `~` в `OUTPUT_FOLDER` означает домашнюю папку пользователя (скрипт разворачивает его сам).

2. **Выбрать видео.** Показать пользователю список видеофайлов в папке (`mp4, mkv, avi, mov, webm, m4a, wav, mp3`) и спросить, какой файл обрабатывать. Ничего не выбирать самостоятельно.

3. **Уточнить место встречи.** Спросить у пользователя переговорную комнату (или ссылку на онлайн-встречу).

4. **Оценить время обработки и получить согласие.** Обязательно ДО запуска распознавания:
   - Узнать длительность видео (через `ffprobe`, а при его отсутствии — `ffmpeg -i <файл>`, строка `Duration:` в stderr).
   - Прикинуть время: на CPU модель `medium` обрабатывает примерно за 1,3–1,5 длительности видео (по замерам: 6-минутное видео — около 7 минут; 56-минутное — около 80 минут). Добавить к оценке несколько минут на анализ расшифровки и сборку протокола.
   - Показать пользователю итог: длительность файла, предполагаемое время обработки и варианты (модель `medium` — как оценили; `small`/`base` — быстрее, но качество русского текста ниже).
   - Дождаться явного согласия пользователя на обработку в обозначенное время. Без согласия не запускать. Если пользователь выбрал другую модель — передать её через `--model`.

5. **Распознать видео.** Запустить:
   ```
   python script/transcribe_meeting.py "<полный путь к видео>" [--model <модель>]
   ```
   Запускать в фоне и следить за прогрессом, чтобы не блокировать сессию. Скрипт печатает JSON с полями `duration_minutes`, `transcript`, `video_modified`. Расшифровка сохраняется в `artifact/<имя>_transcript.md`.

6. **Проанализировать расшифровку.** Из текста расшифровки извлечь:
   - Повестку (краткая тема встречи, 1–2 предложения);
   - Принятые решения, ответственных, ожидаемые даты выполнения.
   Правила: только данные из расшифровки, ничего не выдумывать. Если ответственный или срок не названы — ставить прочерк («—») и сообщить об этом пользователю в итоге.

7. **Создать отчет.** Запустить:
   ```
   python script/create_report.py --transcript "<путь к расшифровке>" \
     --place "<переговорная>" --agenda "<повестка>" \
     --date "<ДД.ММ.ГГГГ ЧЧ:ММ>" --duration <минуты> \
     --output "<имя_видео>_protocol.md" \
     --decision "<решение 1>" --owner "<ФИО>" --due "<ДД.ММ.ГГГГ или —>" \
     --decision "<решение 2>" ...
   ```
   Дату брать из `video_modified` (дата записи видео), если в расшифровке нет явной другой даты. Если имя файла содержит дату и время записи (например, `2026-06-19 12-45-13`) — предпочтительнее она: дата изменения файла может быть моментом копирования, а не записи. Скрипт сам сохранит отчет в папку из `OUTPUT_FOLDER` из `.env` (или в `artifact/`, если переменная пустая) и напечатает итоговый путь.

8. **Показать результат.** Сообщить пользователю путь к отчету и путь к расшифровке. Напомнить, что поля «Организатор встречи» и «Участники встречи» оставлены пустыми для дозаполнения пользователем.

## Требования

- Терминология: «МосИТСМ» (не «Р-Сервис»), «itsm.mos.ru» (не «r-service.tech»), «Портал МосИТСМ», «Консоль МосИТСМ».
- Расшифровки — в `artifact/`, временные файлы — только в `temp/`, итоговые протоколы — в папку из `OUTPUT_FOLDER` из `.env`.
- Зависимости: Python 3.10+, `ffmpeg` и `ffprobe` в PATH, пакет `openai-whisper` (`pip install -U openai-whisper`). При их отсутствии — сообщить пользователю инструкцию по установке простыми словами.
